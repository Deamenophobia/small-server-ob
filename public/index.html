GOOD TO KNOW

A connection, without the clutter.

Start with a host you can already reach from this computer.

01   Add an SSH alias

Add a host to ~/.ssh/config (on Windows, your user folder’s .ssh/config). Use your real hostname and key path. 

Host production-api
  HostName your-server.example.com
  User your-user
  IdentityFile ~/.ssh/your-private-key

02   Verify the connection

Run ssh production-api in your terminal. Verify the host key with your provider before trusting it. If your key is encrypted, unlock it in your SSH agent. Check that python3 is available on the Linux host.

03   Add it to Small Server OB

Choose SSH and enter production-api. Small Server OB reads CPU activity, available memory, and root-filesystem usage using a fixed Python program. It installs nothing and does not need sudo.

CPU ≥ 90%, memory ≥ 85%, or disk ≥ 85% shows a warning. SSH collection time includes login and a short CPU sample; it is not network latency. Failed SSH collection means unknown health.

Prefer a health endpoint?

Choose HTTP for an application health URL, or TCP to check a port. These show reachability and response time; CPU, memory, and disk require SSH.

What about cloud APIs?

AWS CloudWatch and DigitalOcean Monitoring support metric APIs. Memory and filesystem usage require a metric agent or publisher. Cloud health-metric API adapters are not included; provider labels organize your manually added hosts. Billing connections are available separately.

OPTIONAL · READ-ONLY ACCESS

Connect your billing

SSH tells us how a server is doing. Your cloud account tells us what it costs.

DigitalOcean

  1. In API → Tokens, create a token for the correct team with only billing:read.
  2. Save the token in a private local text file outside this project, readable only by your user. Don’t paste it into chat or server notes.
  3. Copy .env.example to .env in the Small Server OB folder and set the token file path: 
LOOKOUT_DO_TOKEN_FILE=C:/Users/YOUR_NAME/.config/lookout/do-token.txt

You can alternatively set DIGITALOCEAN_TOKEN in the app’s process environment. Only the backend reads it.

AWS

  1. Enable Cost Explorer in your billing console. Use a read-only identity with ce:GetCostAndUsage.
  2. Configure a local AWS profile named lookout-billing, preferably using AWS IAM Identity Center, and sign in using the AWS CLI.
  3. Add these lines to Small Server OB’s .env:
LOOKOUT_AWS_BILLING=1
LOOKOUT_AWS_PROFILE=lookout-billing

Run aws configure sso --profile lookout-billing, then aws sso login --profile lookout-billing. Use the account and read-only role supplied by your AWS administrator. Setup guidance: AWS credentials ↗

Restart, then fetch

Restart Small Server OB and click Refresh billing. Queries run only when you request them; successful results are cached locally for six hours. No cloud settings are changed by Small Server OB. Billing may lag behind current usage.

AWS Cost Explorer costs USD 0.01 per primary-view API request. Small Server OB requests one account total per refresh, reuses fresh cache entries, and does not automatically fetch billing during health checks. DigitalOcean shows account usage and balance; AWS shows unblended usage cost, not an invoice amount due.

These are whole-account totals and can include resources outside your saved fleet. A management AWS account may include its organization. One AWS profile and one DigitalOcean team are supported per local app process.
